## งานที่ทำวันนี้

### 1. `ContactEnd` ของการรับสาย = เวลาที่จัดการสายนี้เสร็จ
ไฟล์: [Controllers/ServicesController.cs](../Controllers/ServicesController.cs) (`AddNewService`),
doc comment ใน [Controllers/ContactController.cs](../Controllers/ContactController.cs), [Dtos/ContactResponse.cs](../Dtos/ContactResponse.cs)
และ [Dtos/CreateContactRequest.cs](../Dtos/CreateContactRequest.cs), [AddNewContact.md](AddNewContact.md), [AddNewService.md](AddNewService.md),
`ContactTogetherApi.http`, `CLAUDE.md`

- **ที่มา:** ตรวจว่า `TblContact.ContactEnd` เก็บตอนไหน
  - **API (ก่อนแก้):** ใส่ครั้งเดียวตอน `AddNewContact` เป็นเวลาที่กดปุ่มหลักในกล่องยืนยัน หลังจากนั้นไม่มีที่ไหนแก้
  - **ระบบเดิม** (`GCCWorkspace/2022GCC_Production`):
    - หน้ารับสาย: บันทึก `Contact_Start` = เวลากดบันทึก, `Contact_End` = `NULL` (`Calls/Calls.aspx.cs` ~437-442, ~497-502)
    - เปิดเรื่องใหม่เสร็จ: อัปเดต `Contact_End` เป็นเวลาบันทึกเรื่อง (`Service/Default.aspx.cs` ~674-683)
    - Save As เรื่อง: สร้างแถวใหม่ start = end = เวลาบันทึก
    - ไม่มีที่อื่นใส่ค่านี้ สาย Non-Service และสายที่ไม่ได้เปิดเรื่องใหม่จึงเป็น `NULL` ตลอด
  - **ข้อมูลใน DB ตรงกับโค้ดเดิม:** แถวปี 2014 Non-Service เป็น `NULL` ทั้ง 37 แถว และ Service เป็น `NULL` 164 จาก 979 แถว
  - **ไม่มีที่ไหนอ่าน `ContactEnd`:** ทั้ง API และรายงาน ระบบเดิมก็ไม่ได้ใช้ (`ContactRepo.GetListLevelDetail` ไม่มีที่ไหนเรียก
    และไฟล์ `.rpt` ทั้ง 83 ไฟล์ไม่มีคอลัมน์นี้)
- **ที่แก้ (ตกลงกับผู้ใช้เป็นตัวเลือก "ผสม"):** `AddNewService` เลื่อน `ContactEnd` ของ `contactId` เป็นเวลาบันทึกเรื่อง
  - ใช้ `now` เดียวกับ `TblService.Created` และ `ExecuteUpdateAsync` ใน transaction เดียวกับการสร้างเรื่อง (สร้างไม่สำเร็จ = ไม่เปลี่ยน)
  - เลื่อนไปข้างหน้าเท่านั้น (`ContactEnd IS NULL OR ContactEnd < now`) เปิด 2 เรื่องจากสายเดียว = ได้เวลาของเรื่องหลัง
  - `AddNewContact` ไม่เปลี่ยน: `ContactStart` = เวลาเริ่มสายที่ frontend ส่ง (ไม่ส่ง = เวลาบันทึก), `ContactEnd` = เวลาบันทึก
  - **`AddNewServiceOperations` ไม่เลื่อน** เพราะเรียกจากนอกสายได้ด้วย `contactId` ของงาน Line 1 ถ้าเลื่อน เวลาจบของสายเก่าจะไปอยู่หลายวันต่อมา
  - ผลคือ สาย Non-Service จบที่เวลายืนยัน สายที่เปิดเรื่องใหม่จบที่เวลาบันทึกเรื่อง (ตรงกับระบบเดิม) สายอื่นจบที่เวลายืนยัน
  - ไม่แก้ DB/model และไม่แก้ข้อมูลเก่า response ของ `AddNewService` ไม่เปลี่ยน ไม่ต้องเรียก `NotifyInbox` (ไม่ได้แตะ `TblActivity` หรือสถานะเรื่อง)
- **`ContactStart` ไม่เปลี่ยน:** รายงาน 05/06 นับสายตามวันที่ของค่านี้ frontend จริง (`mui-next-gcc/app/(portal)/calls/page.tsx`)

## วิธีทดสอบด่วน
1. `dotnet run` แล้วรัน `login` ใน `.http` เก็บ `@token`
2. `POST /Contact/AddNewContact` (เบอร์ `0899999999`, `contactStart` ย้อนหลังสักครู่) → 201 `contactEnd` = เวลาบันทึก
3. `POST /Services/AddNewService` ด้วย `contactId` นั้น → 201 แล้ว
   `SELECT ContactStart, ContactEnd FROM TblContact WHERE ID = '<contactId>'` → `ContactEnd` = `TblService.Created` ของเรื่องใหม่
   และงาน Line 1 ของเรื่อง (`GetServiceOperations`) มี `contactId` นั้น
4. `AddNewService` อีกครั้งด้วย `contactId` เดิม → `ContactEnd` = `Created` ของเรื่องที่สอง
5. `AddNewServiceOperations` ด้วย `contactId` เดิม และ `AddNewService` ที่ได้ 400 → `ContactEnd` ไม่เปลี่ยน
