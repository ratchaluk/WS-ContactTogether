## งานที่ทำวันนี้

### 1. `GET /Account/GetAccountById` + `PUT /Account/UpdateAccountById`
ไฟล์: [Controllers/AccountController.cs](../Controllers/AccountController.cs),
[Helper/AccountQueries.cs](../Helper/AccountQueries.cs),
[Dtos/UpdateAccountRequest.cs](../Dtos/UpdateAccountRequest.cs),
[Dtos/AccountSearchResponse.cs](../Dtos/AccountSearchResponse.cs)

- `GetAccountById?id=` คืนผู้ติดต่อ 1 รายในรูปแบบเดียวกับแถวของ `GetAccounts` (ชื่อเพศ + contact details
  ที่เปิดใช้งาน), 404 ถ้าไม่พบ — **คืนบัญชีที่ถูกปิด (`IsEnable != "T"`) ด้วย** เพื่อให้เรื่องเก่ายังแสดง
  ผู้โทรได้ ดูสถานะจากฟิลด์ `IsEnable` (เพิ่มใหม่ใน `AccountSearchResponse`)
- `UpdateAccountById?id=` แก้คอลัมน์ที่แก้ได้ของบัญชี (ชื่อ/เพศ/วันเกิด/ที่อยู่/zip/remark/flags)
  **ไม่แตะเบอร์โทร/อีเมล (`TblAccountDetail`)**; ตั้ง `Updated`/`UpdatedBy` จากนาฬิกา+token, คง `Created*`
  - ใช้ `ExecuteUpdateAsync` แบบ set-based เพราะ `TblAccount.Id` มีแถวซ้ำ (legacy) — UPDATE ทุกแถวของ id
    เดียวกันพร้อมกัน ไม่โดนยุบเหมือน tracked entity
  - `TblArea` ว่าง → `AreaId` เดิมของบัญชีจะไม่ผ่าน lookup check จึงส่ง `keepAreaId` ให้ผ่านค่าที่ไม่เปลี่ยน
    (ถ้า frontend ไม่ได้แก้ช่องนี้ จะ save ได้)
- ดึง query ที่ใช้ร่วมเป็น `ApplicationDbContext.LoadAccountAsync` ใน `Helper/AccountQueries.cs`
- เอกสาร: [GetAccountById.md](GetAccountById.md), [UpdateAccountById.md](UpdateAccountById.md)

ไฟล์: [Controllers/ServicesController.cs](../Controllers/ServicesController.cs),
