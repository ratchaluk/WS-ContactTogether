### 1. `PUT /Services/UpdateService?id=` — แก้ไขเรื่อง + บันทึกการเปิดเรื่องซ้ำ

- **แก้เฉพาะช่องที่ส่งมา:** ไม่ส่ง (`null`) = คงค่าเดิม, ส่ง `""` = ล้างช่องข้อความเป็น NULL
  - `ServiceTitleId` ล้างไม่ได้ (คอลัมน์ NOT NULL) ส่งว่าง = คงค่าเดิม
  - วันที่ (`DateOpened`/`DateClosed`/`OnScene`) ล้างผ่าน request ไม่ได้
- `Updated` = เวลาปัจจุบัน (ตัดเศษวินาที), `UpdatedBy` = `sub` ใน token
- ตรวจ lookup id ทุกตัวด้วย `ValidateLookupsAsync` ตัวเดียวกับ `AddNewService`
- **เปิดเรื่องซ้ำ (reopen):** ถ้าเปลี่ยน `StatusId` เป็น Pending (`19C49E66B6F9EF1BCE11A3B93DED12C8`)
  ให้เรื่องที่ `DateClosed` มีค่า ระบบจะ
  1. เพิ่มแถว `TblReOpenService` (`Line` = Line ล่าสุดของเรื่อง + 1 เริ่มที่ 1, `ReOpenComment`,
     `Closed` = `DateClosed` เดิม, `ClosedBy` = `UpdatedBy` เดิม, `ReOpened`/`ReOpenedBy` = ตอนนี้/ผู้เรียก)
  2. ล้าง `DateClosed` เป็น NULL
  - ทั้งหมดอยู่ใน transaction เดียว และอ่านแถวด้วย `UPDLOCK, HOLDLOCK` กัน update ชนกัน/Line ซ้ำ
- `TblService` เป็น keyless ใน EF model จึงเขียนด้วย `ExecuteSqlInterpolatedAsync` (UPDATE ตรง)
- Response: 200 = service รูปเดียวกับ `AddNewService`; 400 = ไม่มี `id` หรือ lookup ผิด;
  401 = token ไม่มี `sub`; 404 = ไม่พบเรื่องที่เปิดใช้งาน (`ไม่พบข้อมูลเรื่อง`)
- Refactor: ย้ายฟิลด์ที่ใช้ร่วมไปไว้ใน `ServiceFieldsRequest` (abstract) ให้ `CreateServiceRequest` และ
  `UpdateServiceRequest` สืบทอด; แยก helper `Now()` และ `Merge()`
