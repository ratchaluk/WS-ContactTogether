## งานที่ทำวันนี้

### 1. `POST /Services/ReceiveService?id=` — รับงาน (ใหม่)
ไฟล์: [Controllers/ServicesController.cs](../Controllers/ServicesController.cs),
[Dtos/ReceiveServiceResponse.cs](../Dtos/ReceiveServiceResponse.cs) (ใหม่),
[docs/ReceiveService.md](ReceiveService.md) (ใหม่)
(commit `e8850bb` + เอกสาร `16d5d3d`)

- เปลี่ยนงาน (`TblActivity`) ที่เปิดใช้งานของเรื่อง `id` ซึ่งมอบให้ผู้เรียกและยังรอตอบรับ (`IsReceived = F`)
  ให้เป็นรับแล้ว (`T`) ด้วย `ExecuteUpdateAsync` ชุดเดียว แทนการรับอัตโนมัติใน `ViewService.aspx` ของระบบเดิม
- ให้ frontend เรียกตอนเปิดหน้ารายละเอียดเรื่อง เรียกซ้ำได้ (ครั้งต่อไปได้ `receivedCount: 0`)
  **ไม่แตะ `Updated`/`UpdatedBy`** ของงาน
- Response: 200 `{ serviceId, receivedCount }`; 400 ไม่มี `id`; 401 token ไม่มี `sub`; 404 ไม่พบเรื่อง (`ไม่พบข้อมูลเรื่อง`)

### 3. `IsReceived` ให้ server จัดการทั้งหมด
ไฟล์: [Controllers/ServicesController.cs](../Controllers/ServicesController.cs),

อ้างอิงคำอธิบาย `Is_Received` จากโค้ด 2022GCC:
- **ลบ `isReceived` ออกจาก request DTO ทั้ง Add/Update** (ส่งมาถูกข้าม)
- เพิ่มงาน: มอบให้ตัวเอง (`ownerId == sub`) = `T`, คนอื่น = `F`
- แก้งานแล้วเปลี่ยน `ownerId` เป็นคนใหม่ → reset เป็น `F`
- `GetServiceOperations` / รายการงานใน `SearchService` มี `isReceivedText`:
  `รับงานแล้ว` (`T`) / `รอการตอบรับ` (`F`) และ **ว่าง (`""`) เมื่อผู้รับผิดชอบคือผู้สร้างงานเอง**

## วิธีทดสอบด่วน
1. `dotnet run` (ต้องมี user-secrets: `ConnectionStrings:DefaultConnection`, `Jwt:Key` ≥ 32 ตัว)
2. รัน `login` ใน `.http` เก็บ `@token`
3. `POST /Services/AddNewService` → 201 แล้ว `GET /Services/GetServiceOperations?serviceId=<id>`
   ต้องเห็นงาน Line 1 "Call Inbound" สถานะปิด `isReceivedText` ว่าง (ผู้สร้าง = ผู้รับ)
4. เพิ่มงานมอบให้คนอื่น (`ownerId` ≠ ตัวเรา) → งานนั้น `isReceivedText` = `รอการตอบรับ`
5. login เป็นเจ้าของงานนั้น แล้ว `POST /Services/ReceiveService?id=<serviceId>`
   → `receivedCount` ≥ 1; เรียกซ้ำ → `receivedCount` = 0; งานกลายเป็น `รับงานแล้ว`
6. ตรวจ DB: `SELECT Line, Summary, IsReceived, OwnerId FROM TblActivity WHERE ServiceId = '<id>' ORDER BY Line`
